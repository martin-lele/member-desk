# 会员台 · Member Desk

面向中小酒店的本机会员储值管理工具。Python 标准库 + SQLite + 原生 JavaScript，不依赖 Node.js 构建或云数据库。

本仓库是从门店自用系统整理的公开版本，采用**改进版 2** 的使用界面。不含真实会员、员工账号、数据库、令牌、酒店映射或在线试用入口。下载者需独立部署，不连接作者的门店系统。

## 功能

- 会员手机号、生日、身份证资料；身份证默认脱敏显示。
- 会员充值与储值流水，金额按整数分记账；充值门店、业绩归属员工、操作员分别记录。**会员台不提供手动扣款**。
- 管理员、店长、员工三种角色；员工注册时选择门店，人工核实后审批，也可填写原因拒绝申请。
- 全门店共用的本月净充值前三名榜单，以冠军、亚军、季军领奖台展示；按北京时间自然月汇总员工充值及本月发生的充值退款，同额并列，最多展示三人。上门客户和练习记录不参榜。
- 充值业绩查询、退款与纠错申请；管理员审批退款，系统保留处理记录。
- 桌面侧栏与独立工作区域、手机会员列表、姓名或手机号搜索、生日筛选及会员详情。
- 分组充值弹窗：填写金额、核对收款、选择门店和业绩归属；显示预计充值后余额。非现金充值需填写收款流水号，提交前必须确认实际到账。
- 百居易（Hostex）只读 API 客户端及储值房费收款同步适配代码；异常提示与店长跟进记录。

## 日常使用与权限

| 角色 | 主要工作 |
| --- | --- |
| 员工 | 查找和维护会员资料，核对实际收款后办理本店充值，查看流水及同步结果，提交本店原充值流水的退款或纠错申请。 |
| 店长 | 具有员工业务操作权限；审批或拒绝本店普通员工申请、维护本店业绩名单、停用本店普通员工账号，并核对本店储值消费异常、记录跟进事项。 |
| 管理员 | 管理门店及全部团队，任命或撤销店长权限，处理未分配门店的历史申请、退款审批和系统连接配置。 |

员工先收款，后在会员台记录充值；会员台不会自动向客人收款或转账。消费在百居易订单收支中办理，会员台在完成 PMS 适配后自动同步，避免两处重复记账。

## 快速开始

目前支持 macOS / Linux，建议 Python 3.10 及以上。使用 `fcntl`，Windows 暂未适配。

```sh
python3 start.py
```

浏览器自动打开本机初始化页。创建自己的管理员账号、独立密码和首家门店。没有默认账号或默认密码。首次设置密钥保存在 `data/setup-token.txt`，不要分享。

启动脚本在前台运行；保持终端开启，使用 Ctrl+C 退出。端口为 8765，需确保没有其他服务占用。程序和数据均在自己的电脑上。

也可以手动运行 `python3 app.py --port 8765`。首次设置时，在本机地址后追加 `#` 和本机 `data/setup-token.txt` 中的密钥；勿将该地址发送给他人。

## 员工登录

首次员工注册填写真实姓名、与百居易一致的本人前厅账号，选择申请加入的门店，并设置至少 10 个字符的会员台独立密码。所属门店店长或管理员核实本人、百居易账号及前厅身份后审批；门店和业绩员工名单会关联。审批通过后直接登录，同一账号无需重复注册或日常重复审批。

待审批、已停用和已拒绝的账号不能登录。拒绝申请必须填写原因，系统保留处理人和处理时间；已拒绝申请需联系店长或管理员核对，不能直接重新审批。店长只能处理本店普通员工，店长任免由管理员负责；撤销店长权限后仍保留普通员工账号。

百居易同名账号仅用于人工核对，**没有单点登录，不验证百居易密码，也不会自动同步团队权限**。不要将百居易密码或 OpenAPI 令牌填作会员台密码。

本机 `127.0.0.1` 地址不能发给外地员工。远程部署需配置自己的 HTTPS 反向代理，再用 `--public-url https://你的域名` 启动对外入口。监听仅绑定回环地址，代理与应用应在同一主机。

## PMS 适配状态

会员管理可独立使用。公开版本的自动 PMS 扣款**默认未配置、不会自动启用**。源码包含百居易适配器，但不是所有 PMS 的通用即插即用插件。

参考[百居易 API 文档](https://api-doc.myhostex.com/reference/overview)。

部署者需要开发人员完成本账号的付款方式、房费项目、门店分组映射及首次同步起点配置，并用模拟数据核验。保存 API 令牌不代表已经完成接入。

- `HOSTEX_BALANCE_METHOD_ID`：本账号“储值消费”付款方式编号。
- `HOSTEX_ROOM_ITEM_ID`：本账号房费项目编号。
- `member_payment_policy`：数据库 metadata 中与当前付款编号对应的策略。
- `member_payment_group_stores`：数据库 metadata 中的分组编号→本机门店 ID 映射。
- `member_autopay_config`：初次同步时间、授权指纹等启动状态。

这些环境变量不自动创建上述数据库映射，也不能单独启用同步。当前未提供通用配置向导。请在隔离环境完成适配，勿直接修改营业数据库试错。变更付款编号时必须重新核对历史映射。

完成适配后的记账规则：

- 仅按百居易**已确认收款、付款方式为已配置的“储值消费”、项目为房费**的人民币收支记录同步。订单手机号需与会员档案匹配，消费门店需通过房间分组映射确认；混合支付只扣已确认的储值房费部分。
- **未入住、入住中、已退房三个房态本身不触发扣款或退款。** 已确认的储值收款才是记账依据；订单来源、客户姓名、房价和单纯创建订单都不能代替收款记录。
- 更改已确认储值收款金额后，按新旧应扣金额的差额调整余额。仅更改房价，不代表已确认的收款金额也已改变。
- 百居易明确返回**整单已取消**时，该订单应扣金额归零，已由同步记录扣除的余额按差额退回；未扣过的订单不再扣款。部分取消、订单暂时查不到、收款记录删除或无法确认，不会直接当作整单取消退款。
- 缺少手机号、余额不足、门店不明或连接异常时暂停调整，显示待核对原因。员工先核实百居易订单和收支，店长核对流水并跟进；排查期间不要手工重复扣款或充值补差。

公开版本只读百居易，不回写订单、收支或团队权限，也不自动把百居易收入充值进会员卡。充值仍由会员台人工核对实际到账后办理。同步是后台定期核对，不保证保存订单后立即到账，应以会员流水和同步结果为准。

仅本机模式启动同步工作线程；`--public-url` 模式不运行工作线程。部署远程入口时，如要启用 PMS 同步，还需在同一数据目录运行一个本机模式实例，使用不同端口。工作线程启动不代表同步已启用，仍需完成授权、映射和同步起点配置。

## 数据与备份

默认保存在 `data/members.sqlite3`，可用 `MEMBER_DATA_DIR` 指定独立目录；服务和备份命令需使用同一个数据目录。执行 `python3 backup.py` 进行备份，恢复前先停止所有使用该数据库的实例。备份也包含敏感资料，请自行保管并定期验证恢复。API 令牌以主机受限文件保存，不上传仓库。

数据库不是加密数据库。正式使用应配置主机访问控制、磁盘加密、HTTPS、备份和恢复流程。本项目未完成独立安全审计，不应视为经过认证的财务系统。

## 已知限制

短信发送与短信找回密码尚未开通；当前界面中的短信提示不代表可发送，也未提供通用的管理员代重置密码入口。没有百居易团队认证接口，权限需人工审批。公开版本不附带隧道二进制、生产数据迁移脚本或商户专用配置。
